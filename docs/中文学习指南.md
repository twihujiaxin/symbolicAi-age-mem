# AgeMem 中文学习指南

这份指南面向第一次阅读本项目的同学。建议先理解一个可运行的 AgeMem
智能体，再进入三阶段强化学习代码；不要一开始就从 Trinity-RFT 的训练器底层读起。

## 1. 先建立整体认识

AgeMem 的核心思想是：把记忆管理也视为智能体可以自主选择的动作。

- 短期记忆（STM）就是当前上下文 `context_messages`。
- 长期记忆（LTM）是上下文之外的向量存储 `MemoryManager`。
- 模型除生成普通文本外，还可以调用 6 个工具：
  - LTM：`Add_memory`、`Update_memory`、`Delete_memory`
  - STM：`Retrieve_memory`、`Summary_context`、`Clear_context`
- 训练并不只奖励最终答案，还评价上下文压缩、记忆质量和工具效率。
- Step-wise GRPO 用整条轨迹的最终结果，为前面的存储、检索、过滤等动作分配信用。

一次训练 rollout 可以画成：

```text
HotpotQA 样本
  |
  +-- Stage 1：把样本 context 包装成闲聊
  |     模型学习判断哪些事实值得写入 LTM
  |
  +-- 清空 STM（LTM 不清空）
  |
  +-- Stage 2：注入与问题无关的干扰对话
  |     模型学习 Summary / Clear（在线路径可能调用冻结的 qwen-max）
  |
  +-- Stage 3：提出正式问题
        模型通过 Retrieve 取回 Stage 1 的记忆并作答
  |
  +-- 多维奖励 -> Step-wise GRPO -> 更新模型策略
```

## 2. 目录怎么分层

### 第一层：最小可运行智能体

`AgeMem_code_agentscope/` 是脱离强化学习训练框架的 AgentScope 示例。

- `main.py`：命令行入口，创建模型和 AgeMem 智能体。
- `agent.py`：ReAct 循环以及 6 个工具的完整实现。
- `memory.py`：内存向量库、Embedding 和长期记忆接口。
- `prompts.py`：摘要、相似度判断等提示词。
- `src/`：输出结构、模型客户端和少量辅助函数。

这部分最适合先读，因为它直接回答“一个 AgeMem 智能体运行时怎样思考和调用工具”。

### 第二层：论文核心训练工作流

`trinity/common/workflows/memory_context/` 是论文方法的主要实现。

- `train_hotpotQA.py`：三阶段 rollout 的训练入口，也是最核心文件。
- `eval_hotpotQA.py`：评估流程；结构与训练相似，但额外统计评估指标。
- `utils.py`：6 个工具的 JSON Schema、工具调用解析和干扰项生成。
- `memory_store.py`：训练工作流使用的轻量长期记忆库。
- `workflow_prompt.py`：要求模型输出 `<tool_call>` / `<answer>` 的系统提示。
- `workflow_metrics.py`：答案、supporting facts 和联合指标。

### 第三层：奖励和策略优化

- `trinity/common/workflows/memory_reward/my_reward.py`
  - 汇总工具、上下文和长期记忆统计；
  - 计算任务、STM、LTM、工具效率四类奖励。
- `trinity/algorithm/advantage_fn/multi_step_grpo_advantage.py`
  - 按 task 和 run 组织 Experience；
  - 用同一问题的多个 rollout 做组内标准化；
  - 把轨迹分数广播给该轨迹的所有历史动作。

### 第四层：Trinity-RFT 通用底座

以下目录主要是通用强化学习基础设施，第一遍只需知道职责：

- `trinity/explorer/`：并发生成 rollout。
- `trinity/buffer/`：存储和预处理 Experience。
- `trinity/trainer/`：调用 VeRL 执行反向传播和参数更新。
- `trinity/manager/`：配置与训练状态管理。
- `trinity/algorithm/`：GRPO/PPO 等算法组件。

它们不是 AgeMem 论文创新点。只有在需要改训练调度、显存策略或 Experience
数据流时，才需要深入。

## 3. 推荐阅读顺序

### 第 1 遍：只看推理，不看训练

1. `AgeMem_code_agentscope/main.py`
2. `AgeMem_code_agentscope/agent.py` 的 `__init__` 和 `reply`
3. `agent.py` 中 6 个工具方法
4. `AgeMem_code_agentscope/memory.py`

读完应能回答：

- STM 和 LTM 分别存在哪里？
- 模型如何决定继续调用工具还是结束回答？
- `Retrieve_memory` 为什么属于 STM 工具？

答案是：Retrieve 不修改长期存储，而是把 LTM 内容拉入当前上下文。

### 第 2 遍：理解三阶段数据构造

1. `examples/agemem_hotpotqa/agemem_train.yaml`
2. `train_hotpotQA.py::run_async`
3. `train_hotpotQA.py::inference_samples`
4. `_run_stage1_casual_chat`
5. `_run_stage2_distractor_injection`
6. `_run_stage3_formal_qa`
7. `_apply_tools`

重点跟踪三个变量：

- `context_messages`：会在 Stage 1 与 Stage 2 之间清空。
- `memory_manager`：同一次 rollout 的三个阶段共享。
- `all_stage_experiences`：收集三个阶段中需要学习的模型动作。

### 第 3 遍：理解奖励和信用分配

1. `my_reward.py::extract_*_stats`
2. `ThreeStageRewardCalculator.calculate_total_reward`
3. `_context_quality`
4. `_memory_quality`
5. `_tool_policy`
6. `StepWiseGRPOAdvantageFn.process`
7. `StepWiseGRPOAdvantageFn.broadcast_advantages`

可以用下面的简化公式理解：

```text
R_total =
    w_task    * R_task
  + w_context * R_context
  + w_memory  * R_memory
  + w_tool    * R_tool
  + penalties

A(run) = (R(run) - 同题各 rollout 平均奖励) / 标准差
```

然后 `A(run)` 会赋给该 run 内每个 Experience 的有效 action token。

## 4. 论文概念与代码映射

| 论文概念 | 代码位置 |

## 5. 阅读时要留意的实现细节

1. 代码中的“清空上下文”不等于遗忘长期记忆。Stage 2 前只执行
   `context_messages.clear()`，没有执行 `memory_manager.clear()`。
2. `memory_manager.clear()` 只在开始新的 rollout 时调用，避免不同样本或不同
   rollout 相互泄漏记忆。
3. 工具调用是模型输出的文本协议。训练工作流通过 `parse_tool_calls` 解析
   `<tool_call>` 块，再由 `_apply_tools` 真正修改状态。
4. `Experience` 是训练样本，不等同于对话消息。对话存于
   `context_messages`，而 token、action mask、reward 等训练数据存于 Experience。
5. 当前训练代码使用的奖励权重是 `0.5 / 0.2 / 0.15 / 0.15`
   （任务 / 工具 / 上下文 / 记忆）。阅读论文公式时应以实际运行配置和代码为准。
6. `extract_context_stats` 使用“字符数 / 4”估算 token，并非精确 tokenizer 计数。
7. 训练文件给同一轨迹的所有 Experience 写入相同终局奖励；Step-wise GRPO
   再在组内标准化并按 `action_mask` 广播 advantage。

## 6. 建议的学习练习

1. 在独立 AgentScope 示例中打印每轮 `context_messages`，观察一次 Add 和 Retrieve。
2. 手工构造 3 条 `MemoryItem`，验证余弦相似度检索顺序。
3. 把 `repeat_times` 暂时理解为同题采样的 K 条候选轨迹，手算一次 GRPO 标准化。
4. 在 `inference_samples` 中画出一个 Experience 的 `eid.task/run/step`。
5. 最后再尝试修改一个奖励权重，观察工具调用次数和答案质量如何变化。
